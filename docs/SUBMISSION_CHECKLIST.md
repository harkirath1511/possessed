# Submission checklist

## Required by the challenge

- [ ] New project created during the challenge entry period; verify the official rules before publication.
- [ ] Open-source AI is central to the working project, with its exact model/framework identified.
- [ ] Explain the Ghost in the Machine theme and why the open approach matters.
- [ ] Provide a working demo link or genuine demo video.
- [ ] Provide the code repository and original-code license.
- [ ] Publish an English-language DEV post using the challenge template and `devchallenge`, `hf26challenge` tags.
- [ ] Verify entrant eligibility against the official rules (18+ and permitted jurisdiction).
- [ ] Submit before 2026-11-01 12:29 IST / 2026-10-31 23:59 PDT.

Official rules: https://dev.to/page/hacktoberfest-week4-2026-10-26-contest-rules
General rules: https://dev.to/page/official-hackathon-rules
Challenge: https://dev.to/challenges/hacktoberfest-week4-2026-10-26

## Technical proof

- [ ] Clean note completes ticket #104 without changing #666.
- [ ] At least one genuine attack run is recorded. If the model resists, report that result honestly.
- [ ] Run the same attack note with the same model in the other authorization mode.
- [ ] Protected mutation endpoint denies #666 while allowing #104.
- [ ] Export actual records and screenshots. Exclude fixture playback from reported model outcomes.
- [ ] Verify cancellation, error display, mobile layout, keyboard controls and reduced motion.
- [ ] Run `npm run check`, browser smoke check, and advisory check on final dependency versions.

## Sponsor evidence

- [ ] Gemma: completed real inference, exact model ID, and a run showing its role.
- [ ] Browserbase: completed cloud browser session, actual session ID and captured observation. Local Stagehand use alone does not establish hosted Browserbase use.
- [ ] Sentry Agent Tracing: actual received agent/model/tool trace, screenshot, latency and debugging explanation.
- [ ] Render: deployed service URL, successful health response and working runtime.
- [ ] Only list the categories with evidence above. Do not infer prize eligibility from installing packages.

## Publishing

- [ ] Review the exact DEV draft, replacing pending links and observations with verified facts.
- [ ] Check repository contents for `.env`, access tokens, provider keys, runtime data and unlicensed assets.
- [ ] Confirm the author identity and the user's authorization before publishing the DEV post.
- [ ] Check the final public demo and repository as a visitor.
